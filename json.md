# JSON библиотеки дла java
## 1. Jackson
   Jackson — это де-факто стандарт для работы с JSON в Java-экосистеме, предлагающий исключительную гибкость и производительность.

> Типы файлов: Помимо JSON, Jackson поддерживает широкий спектр форматов данных через отдельные модули: YAML, XML, CSV, Avro, Protobuf, CBOR, Smile (бинарный JSON), BSON, Java Properties и другие.

> Способы работы с файлами: Библиотека предлагает три модели: Потоковый API, Объектная модель, Привязка данных
1. Потоковый API (Streaming API): Низкоуровневый, самый быстрый и экономичный по памяти способ (JsonParser/JsonGenerator).
2. Объектная модель (Tree Model): Представление JSON в виде дерева (JsonNode).
3. Привязка данных (Data Binding): Автоматическая сериализация/десериализация Java-объектов (POJO) с помощью ObjectMapper.
Особенности работы с датой/временем: Для типов java.time (например, LocalDateTime) требуется подключение модуля jackson-datatype-jsr310 и регистрация JavaTimeModule. Без этого модуля сериализация дат нового образца не поддерживается.

> Особенности работы с большими файлами: Благодаря Streaming API Jackson может обрабатывать файлы практически любого размера, не загружая их целиком в память. Вы читаете файл токен за токеном, что позволяет избежать OutOfMemoryError.

> Иные особенности: Славится высокой производительностью в «прогретом» режиме (warm throughput) и лидирует по скорости десериализации среди основных конкурентов. Имеет огромное сообщество и обширную документацию.

## 2. Gson

Gson — простая и легковесная библиотека от Google, которая долгое время была стандартом де-факто для Android-разработки.

> Типы файлов: ориентирована исключительно на JSON. Поддержка других форматов не является её целью.

> Способы работы с файлами: в основном используется для привязки данных (Data Binding) и поддерживает потоковый парсинг.
1. Привязка данных (Data Binding): сериализация/десериализация POJO с помощью класса `Gson`.
2. Потоковый парсинг: чтение и запись через `JsonReader`/`JsonWriter`.

Особенности работы с датой/временем: долгое время не имела встроенной поддержки `java.time`. Начиная с версии 2.14.0, Gson получил встроенные (first-party) адаптеры для `java.time` (`Instant`, `LocalDate`, `LocalDateTime` и др.), что упростило работу. Ранее требовалось писать собственные `TypeAdapter`.

> Особенности работы с большими файлами: как и Jackson, Gson поддерживает потоковый парсинг с помощью `JsonReader`. Это позволяет читать данные инкрементально, не загружая весь файл в память, что критично для больших документов.

> Иные особенности: имеет один из самых быстрых показателей «холодного старта» (время от запуска до первого полезного результата). Прост в освоении и не требует сложной настройки для базовых сценариев.

## 3. Moshi

Moshi — современная библиотека, созданная как более строгая и предсказуемая альтернатива Gson, с особым фокусом на поддержку Kotlin.

> Типы файлов: работает только с JSON.

> Способы работы с файлами: предоставляет высокоуровневый API для привязки данных и низкоуровневый потоковый API.
1. Привязка данных: работа через `JsonAdapter`.
2. Потоковый API: чтение и запись через `JsonReader`/`JsonWriter`.

Особенности работы с датой/временем: не имеет встроенной поддержки `java.time`. Для работы с датами требуется явная регистрация специального `JsonAdapter`, например `Rfc3339DateJsonAdapter` для `java.util.Date` или собственного адаптера для `java.time`.

> Особенности работы с большими файлами: поддерживает потоковое чтение через `JsonReader`. Благодаря ленивой загрузке (значение парсится только при обращении к полю) и использованию Okio для ввода-вывода, Moshi показывает более низкое потребление памяти по сравнению с Gson (примерно на 40% в некоторых тестах).

> Иные особенности: отличается строгим подходом к дизайну API (меньше «магии»), что делает поведение библиотеки более предсказуемым. Имеет мощную поддержку полиморфной сериализации через `PolymorphicJsonAdapterFactory`.

## 4. JSON-P / JSON-B (Jakarta JSON Processing / Binding)

Это стандартные API Java EE (ныне Jakarta EE) для работы с JSON. JSON-P (Processing) — для парсинга и генерации, JSON-B (Binding) — для привязки объектов. Для использования требуются реализации, например Eclipse Yasson или Apache Johnzon.

> Типы файлов: стандарт определяет работу с JSON. Однако JSON-P предоставляет возможность создавать собственные провайдеры для других форматов.

> Способы работы с файлами: API чётко разделяет две модели.
1. JSON-P (Processing): потоковый API (`JsonParser`/`JsonGenerator`) и объектная модель (`JsonObject`, `JsonArray`).
2. JSON-B (Binding): привязка данных (сериализация/десериализация POJO), аналогично Jackson `ObjectMapper` или Gson.

Особенности работы с датой/временем: JSON-B имеет встроенную поддержку формата ISO 8601 для типов даты и времени по умолчанию, что соответствует спецификации Jakarta JSON Binding.

> Особенности работы с большими файлами: использование потокового API JSON-P (`JsonParser`) является предпочтительным для обработки больших объёмов данных, так как он более эффективен по памяти и производительности, чем объектная модель, которая загружает весь JSON в память.

> Иные особенности: является стандартом для Java EE/Jakarta EE, что обеспечивает переносимость кода между разными реализациями (Yasson, Johnzon и др.). Это делает его привлекательным для корпоративной разработки, где важна стандартизация.

## 5. JsonPath

JsonPath — это не библиотека для полной сериализации/десериализации, а инструмент для навигации и извлечения данных из JSON-документов с использованием синтаксиса, похожего на XPath.

> Типы файлов: работает с JSON. Архитектура на основе провайдеров (SPI) позволяет подключать различные парсеры JSON, такие как Jackson, Gson или Jakarta JSON-P.

> Способы работы с файлами: основное назначение — парсинг и извлечение данных; некоторые реализации также поддерживают полную сериализацию/десериализацию.
1. Извлечение данных по пути: например, `$.store.book[0].title`.
2. Сериализация/десериализация: поддерживается в отдельных реализациях, например в Snack3.

Особенности работы с датой/временем: JsonPath сам по себе не управляет типами данных. Он извлекает значения (строки, числа) из JSON. Преобразование в конкретный тип (например, `LocalDateTime`) должно выполняться уже после извлечения, в коде на Java.

> Особенности работы с большими файлами: традиционные реализации JsonPath обычно требуют полной десериализации JSON в объектную модель (например, в `Map` или `JsonNode`) перед выполнением запроса, что может быть проблематично для очень больших файлов. Однако существуют оптимизированные фреймворки (например, SJF4J), которые могут применять JSONPath напрямую к POJO или потокам, избегая создания промежуточного дерева в памяти.

> Иные особенности: незаменим для задач, где нужно быстро извлечь небольшой фрагмент из большого, сложного JSON-документа, не описывая для этого всю структуру классами. Это делает его мощным инструментом для анализа данных и работы с API.
